# REST API Reference

**Source of truth:** the live OpenAPI schema at `/openapi.json` (interactive docs at `/docs` when
the backend is running). This file is a human-readable index of what exists, not a
re-derivation of every request/response schema — those are generated into
`packages/desktop-types/src/api.d.ts` (see ADR 0007) and drift-checked there, not duplicated here
by hand. Base URL in development: `http://127.0.0.1:8000`.

All endpoints below are real — this list was generated by starting the real backend and reading
its real live schema (2026-08-11), not transcribed from a design doc.

## Health

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/health` | none | Always 200 — for load balancers |
| GET | `/health/live` | none | 200 if the process is running (Docker `HEALTHCHECK` target) |
| GET | `/health/ready` | none | 200 only if DB + Redis are actually reachable (real `SELECT 1`/`PING`) |

## Auth (`/api/v1/auth`) — see `AUTHENTICATION.md` for the full token-lifecycle explanation

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/register` | none | Create an account |
| POST | `/login` | none | Email/password → access + refresh token pair |
| POST | `/refresh` | refresh token | Rotates the refresh token, issues a new access token |
| POST | `/logout` | access token | Revokes the current refresh token |
| GET | `/me` | access token | Current user's profile |
| GET | `/oauth/{provider}` | none | Redirects to the OAuth provider's consent screen (`github`/`google`) |
| GET | `/oauth/{provider}/callback` | none | OAuth callback — exchanges the provider's code for a session |

## Workspaces (`/api/v1/workspaces`)

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/` | access token | Register a workspace root path — idempotent by `(user, root_path)`; opening an already-known folder bumps `last_opened_at` instead of duplicating |
| GET | `/` | access token | List the current user's workspaces |
| GET | `/{workspace_id}` | access token | Get one workspace (404, not 403, if it belongs to someone else — don't leak existence) |
| PATCH | `/{workspace_id}` | access token | Update workspace metadata |
| DELETE | `/{workspace_id}` | access token | Remove a workspace record |

Not built: `/workspaces/{id}/index` and `/workspaces/{id}/files/*` — both deferred, see ADR 0004
(indexing needs the Celery infrastructure that was never actually stood up) and `TASKS.md`.

## Chat (`/api/v1/chat`)

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/sessions` | access token | Create a chat session |
| GET | `/sessions` | access token | List the current user's sessions |
| GET | `/sessions/{session_id}` | access token | Get a session + its full message history |
| DELETE | `/sessions/{session_id}` | access token | Delete a session |
| POST | `/sessions/{session_id}/messages` | access token | Send a message — persists it, returns `201` immediately, then streams the AI reply over the WebSocket gateway (`stream_chunk`/`stream_end`, see `WEBSOCKET_EVENTS.md`) rather than in the HTTP response body |

## Agents (`/api/v1/agents`)

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/tasks` | access token | Start an agent task — dispatches to a real Celery worker (`run_agent_task.delay()`, see ADR 0004) and returns immediately with the `pending` row |
| GET | `/tasks` | access token | List agent tasks |
| GET | `/tasks/{task_id}` | access token | Get one task |
| GET | `/tasks/{task_id}/steps` | access token | Get a task's recorded steps (`agent_task_steps`, see ADR 0009) |
| POST | `/tasks/{task_id}/approve` | access token | Approve or reject a pending high-risk action (see the `agent_approval_required` WebSocket event) |
| POST | `/tasks/{task_id}/answer` | access token | Answer a pending `ask_followup_question` (see the `agent_question_asked` WebSocket event) — distinct from `/approve`, a free-text answer rather than a yes/no decision |
| POST | `/tasks/{task_id}/cancel` | access token | Cancel a running task |

## Models (`/api/v1/models`)

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/` | access token | List models `ModelRouter` knows how to route to (the same static catalog it uses for context-window/truncation decisions — not a live per-provider "list your models" call, see `MODEL_ROUTER.md`) |
| GET | `/ollama/installed` | access token | List models actually installed on the configured Ollama server (a live call, unlike `GET /` above) |
| POST | `/ollama/pull` | access token | Pull an Ollama model — streams Ollama's own real download progress back as newline-delimited JSON (`{status, total, completed, error}` per line), not a one-shot response |
| DELETE | `/ollama/{model_name}` | access token | Remove an installed Ollama model |
| GET | `/{model_id}` | access token | Get one model's metadata |

## Git (`/api/v1/git`)

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/generate-commit-message` | access token | Sends a staged diff through `ModelRouter` and returns an AI-generated commit message — the only git-related backend endpoint; everything else (status/stage/commit/diff/log/branches/push/pull) is a local Electron IPC call to a real `git` subprocess, not a backend API (see ADR 0008) |

## Not-yet-built routers named in design docs

`API_SPECIFICATION.md` originally sketched routers this backend doesn't have yet: a dedicated
search/RAG endpoint (RAG happens inline inside `chat`'s context builder, not as its own API), and
a plugin-management API (no plugin runtime exists — see `docs/plugin-authoring/README.md`'s own
honest scope note). Not silently dropped — tracked in `TASKS.md`.
