# apps/backend/alembic/versions/

Individual Alembic migration scripts. One file per schema change, generated by `alembic revision`.

## Naming Convention

Alembic auto-generates the filename with a revision hash prefix:

```
0001_abc12345_initial_schema.py
0002_def67890_add_workspace_memories_table.py
0003_ghi11111_add_agent_audit_log_table.py
```

## File Contents

Each migration has two functions:
- `upgrade()` — applies the change (adding tables, columns, indexes)
- `downgrade()` — reverses the change

## Rules

- Never edit a migration that has been applied to a shared environment.
- Always include a `downgrade()` — even if it's a destructive `DROP TABLE`, it must exist.
- For data migrations: read data in `upgrade()`, write it back in the new format. Document data migrations prominently.
- Index creation for large tables should use `CREATE INDEX CONCURRENTLY` in raw SQL (not detectable via autogenerate).
